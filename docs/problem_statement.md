# Постановка задачи

## Актуальность
Система видеонаблюдения важна для безопасности объектов, контроля событий и быстрого реагирования на неисправности оборудования. Пользователь должен видеть онлайн-трансляцию, находить запись в архиве и сообщать о проблемах без перехода между разными сервисами.

## Ограничения
- В репозитории не хранятся реальные видеозаписи и персональные данные.
- Для демонстрации используются только обезличенные примеры камер, событий и заявок.
- Проект ограничен учебной разработкой структуры, требований, метрик и прототипных материалов.
- В системе должны учитываться роли клиента, администратора и установщика.

## Критерии успешности
1. Описаны основные сценарии: просмотр камер, доступ к архиву, создание и обработка заявки.
2. Определены роли пользователей и правила доступа к функциям.
3. Сформулированы метрики качества и удержания клиентов.
4. Подготовлена структура репозитория для дальнейшей разработки.

## Риски
- Недоступность камеры снижает доверие к системе; риск уменьшается через статусы камер и уведомления.
- Неудобный архив мешает расследованию инцидентов; риск уменьшается через поиск по дате и событиям движения.
- Заявки могут обрабатываться медленно; риск уменьшается через приоритеты, статусы и историю обработки.

Непроверенное утверждение: все камеры системы всегда доступны без технических сбоев.
